# 采购方与供应商本体领域术语

此词汇表描述采购需求与供应商能力共享的业务语义；详细决策见[决策地图](./map.md)。

## 分类

**采购负责类**：
三级分类树的顶层节点；其下包含一级品类。

**一级品类**：
只归属于一个采购负责类的中层分类节点；其下包含二级品类。

**二级品类**：
只归属于一个一级品类的叶节点；采购需求和乙方能力均可引用它。

**通用分类模板**：
平台维护的可版本化三级分类树，供企业采用以建立本企业分类树；模板更新不直接改变企业树。

**企业分类树**：
一家甲方或乙方采用通用模板并按本企业需要维护的三级分类树；可有本地修改和新增节点。

**品类语义匹配**：
甲方发起采购需求匹配时，系统比较甲乙方分类树中完整三级路径及描述，判断两个二级品类是否语义等价，用于筛选可能供应该采购项的乙方；同名不自动等价，包含关系不自动算匹配。品类匹配本身不判断入围。

## 企业

**乙方能力**：
某个乙方已确认可提供的服务或物料记录，引用一个二级品类；它不等于分类节点本身。
_避免_：用“所属采购负责类”代替具体能力。

**乙方事实**：
乙方已确认发布的资格、品牌、服务团队、案例或服务承诺等独立记录，可关联多条能力；带原文来源、适用范围及生效/到期时间。能力关联不扩大事实原有范围。

**乙方临时能力**：
乙方为某采购项目声明、但尚未在已发布本体中形成相应能力的项目输入；可带未发布的临时完整三级路径供本项目品类初筛，不进入常规供应商检索。新路径节点与能力另成待确认候选。

**企业本体视图**：
一家甲方或乙方在共享核心语义上组织自身信息、业务事项和对方相关信息的视图。
_避免_：甲方本体与乙方本体是两套互不相容的分类体系。

## 采购需求

**采购项**：
一次采购需求拆分出的单元，引用一个二级品类，并承载本次采购专属的条件集合。

**采购需求采集字段**：
企业本体按二级品类定义的本次采购应收集的数据及其必填性、类型、单位、范围和条件依赖；具体取值由采购员确认并保存在外部采购系统。

**供应商条件模板**：
企业本体按二级品类提供的可复用准入与评分条件建议；本次采购项的具体条件、门槛和权重仍由采购员确认，不固定在分类节点上。

**二级品类知识包**：
甲方企业本体中与某个二级品类关联的可引用条目集合，分条组织需求采集字段、供应商条件模板、判定说明及解释文字；结合外部系统传入的本次取值与乙方本体事实、本次材料或逐条件声明，供本工程判定。知识包不等于分类树节点，也不代替本次采购项的具体条件。

**企业约束规则**：
企业本体中经确认发布、带有适用范围与生效时间的业务限制，例如餐标上限；从企业资料提取时先是本体候选。硬约束按自身范围生效，即使知识包未引用它，本次采购输入也不能覆盖。它不同于知识包给出的默认采购建议。

**需求数据齐备**：
本工程按最新已发布企业本体与分类树校验本次采购草案，未发现必填缺失、无效值、硬约束冲突或未确定的适用流程的状态；不表示外部系统已批准或发布采购。

**初步入围**：
甲方外部业务系统允许乙方参与某次采购的投标或竞标，可由甲方授权人员确认，也可在甲方企业政策及本次采购均预授权、所有必须项机器通过时自动记录；不表示中标或签约。本工程只提供判定，不记录该状态。

**必须项**：
采购项中须通过、乙方才能初步入围的条件；可按已发布规则或 LLM 判定。乙方针对本次条件的明确诚信声明可参与自动判定，须标明自述来源。可计分并单设最低通过分，计分必须项得 0 分必定不通过；入围截止仍缺相关内容或声明按不满足处理。

**乙方本次声明**：
乙方针对某次采购的具体条件作出的回答或承诺，记录原话、身份、时间和来源项目；资格预审可按诚信申报将其作为本次判定依据，即使未上传证明文件。它不是已发布本体事实；与旧事实冲突时须显示冲突，并作为待确认候选供乙方后续审核。可复用的承诺经管理员发布后默认作为通用事实；原话或材料明确限定项目、品牌、地域、品类或时间时仍按限制适用。

**乙方自检建议**：
供应商 Agent 用本次需求及乙方本体和材料取得的可响应判断；不改变甲方结果，也不表示外部系统已正式入围。

**自动入围政策**：
甲方企业本体中已确认发布的自动判定规则；本次采购还须在外部系统显式启用。符合政策且**全部必须项均可机器判定并通过**后，本工程可返回“符合自动入围条件”，正式入围由外部系统记录。

**加分项**：
采购项中不影响初步入围、仅影响后续评标得分的条件；“选择性满足项”按此类处理。

**条件满分**：
一个采购项内某项评分条件可获得的最高分；同一采购项的可计分条件满分合计为 100 分。

**采购项汇总权重**：
单一供应商采购时，将多个采购项的百分制得分合成为总分所用的比例；同次采购的各项权重合计为 100%。

## 职位与流程

**职位**：
一家企业定义的岗位名称、职责和业务权限的集合；可由多人任职。

**任职**：
人员与企业职位之间的关系；人员的直接上级不由此关系定义。

**企业审批流程**：
企业确认的、按条件指定审批职位和顺序的流程；在办采购沿用其启动时的流程版本。

## 本体确认

**本体陈述**：
已发布本体中一条可单独引用的事实或关系，记录主体、关系、客体或值、适用范围、有效期、来源和版本；图上可显示为节点属性或连线，但展示形式不改变其独立身份。本次采购的乙方声明是项目输入，确认发布前不是已发布本体陈述。

**首次投喂结构**：
企业尚无已确认业务 schema 时，用`Class`、`Property`、`Relation`、`Constraint`、`Instance`五种通用结构承载从企业原文提出的定义或事实；它们是提议的类型，不预先决定该企业的业务术语。分类树候选独立发布。

**本体候选**：
从自然语言、Markdown 或本次采购中已确认的新条件及乙方新声明提取、尚未被企业确认发布的类、属性、关系、约束或事实提议。用户所说的“待定本体知识”在本规格中称为本体候选。资料投喂形成的候选须能定位支持它的原文；找不到依据的推断只是`MODEL_SUGGESTION`，不能作为事实候选。草案中的临时建议还不是候选；整份条件快照确认后可自动去重入待审队列，但候选自身不是已发布事实。

**来源修订与拟替代关系**：
同一企业资料以逻辑来源 ID 关联多个不可改修订；新版明确更改旧内容时，新候选用`proposed_replaces`指向旧内容，等待人工确认和发布。新版未提及旧条目不表示自动撤销。

**已确认本体内容**：
有本企业确认权限的人确认采纳的候选，或在图上保存并确认的修订；须经企业本体版本发布后才供新业务事项和 Agent 使用。原文证据和人工编辑记录分别保留。

**本体变更批次**：
一家企业一次待发布的业务本体变更集合；批次内每条候选须确认采纳或拒绝，企业管理员在校验通过后整批发布。同一企业同时最多有一个待发布批次。

**发布依赖闭包**：
业务本体批次中的每条已采纳内容，其引用对象须已发布或在同批采纳；新分类节点须先进入已发布企业树。依赖被拒绝或未确认时，相关内容不能发布。带拟替代关系的规则还须确认旧规则终止及新规则开始生效时间。

**企业本体版本**：
企业管理员将一个本体变更批次发布后形成的不可改快照；新事项使用最新版，历史和在办事项保留其启动时版本。

**普通 Agent 本体读取**：
先按自然语言或关键词搜索已发布条目，再按稳定 ID 读取有权可见的详情与来源片段；通用核验可直接接收自然语言问句和可选主体 ID，返回解析出的命题、`支持 / 反驳 / 依据不足 / 冲突`及真实证据路径。普通操作只查当前最新版。按 ID 读取只给直接相邻的一跳关系摘要；问答搜索可按问题相关性沿真实、有类型的关系最多扩展三跳，不能凭可达性认定业务条件满足，也不能把缺失当成否定。主体歧义、门槛不明或缺少本次采购条件均说明依据不足，外部 Agent 自行决定后续动作。项目声明与准入由专用判定处理；旧事项的判定仍内部使用绑定快照，历史解释通过具体判定审计引用，不开放任意旧版本体搜索。

## 复用层次

**通用基线**：
从已确认的企业本体总结、由平台发布的可版本化通用业务定义；企业固定引用自己采用的版本。

**企业专属定义**：
仅属于一家企业的类、属性、关系或约束，可与该企业的实例并存，不自动改变通用基线。

**共性候选**：
同类业务中三家独立企业各有已确认的语义相似内容时，提交平台审核的待定通用定义；相似不等于已判定等价。
