# 企业资料投喂与本体候选：最小契约（设计稿）

状态：产品接口规格，尚未实现；操作名用于说明行为，HTTP 路径和存储方式未冻结。决策见[首次资料投喂票据](../issues/25-define-initial-ontology-ingestion-contract.md)。

## 输入与权限

`ingest_enterprise_source`由有本企业资料维护权限的用户或限定服务身份调用。服务端从认证上下文确定企业，不接受仅凭请求体中的企业 ID 跨企业写入。一次提交至少包含：逻辑`source_id`、不可变`source_revision`、来源类型（自然语言或 Markdown）、原文、提交人及时间；Markdown 另有文件名，原件保留在该企业空间。修订同一资料时沿用`source_id`、提交新的`source_revision`，不能就地改写旧版。每次抽取记录所用模型与提示配置版本。

本工程保存资料来源及其修订，用于本体候选与已发布内容的追溯；外部采购系统仍保存聊天、采购草案和采购业务状态。投喂资料的正文只对本企业有权人员和被授权的后台任务开放。

## 首次抽取的结构

首次尚无企业业务 schema，使用以下**技术承载结构**表示提议，而不预先规定该企业的采购岗位、流程、品类或服务含义：

| 类型 | 候选所表达的内容 | 示例 |
| --- | --- | --- |
| `Class` | 一类业务对象的定义 | “职位”“审批流程” |
| `Property` | 可记录的字段或连接两个对象的谓词定义 | “审批金额阈值”及其单位；“直接上级”这一关系的定义 |
| `Relation` | 具体主体通过已定义谓词连接客体形成的可引用陈述 | “甲公司的采购经理职位，直接上级是采购总监职位” |
| `Constraint` | 适用范围、条件或限制 | “超过 500 万元需三级审批” |
| `Instance` | 该企业的具体业务对象或事实 | “采购经理”职位、“上海服务团队” |

一条来源可产生多种类型的提议。抽取结果须区分**定义**和**实例**，并给出彼此引用；引用尚未确认的定义时，发布前须一起解决。三级分类树节点属于独立版本化的企业树：抽取出的采购负责类、一级品类、二级品类及父子关系进入**分类树候选**，不能仅因承载形式是`Instance`或`Relation`就混入业务本体发布批次。

五种技术承载结构与已发布 RDF 词汇的映射见[词汇与 SHACL 发布校验设计稿](../ontology/rdf-vocabulary-shacl-v0.md)。`Constraint`是企业业务规则候选，不直接变成 SHACL 形状；平台基础形状只验证拟发布本体的结构。

有了已确认并发布的业务 schema 后，再按该 schema 提取新候选；仍逐项保留来源并由人确认。通用基线的采用或升级不自动确认企业新资料。

## 候选、建议与来源

每个可审核候选至少返回：候选 ID、上述类型、拟议内容、所引用对象、来源 ID/修订、足以支持该内容的**原文片段及位置**、适用范围和有效期（原文有表达时）、模型与提示版本、可能的冲突或替代目标。自然语言来源还须可追到说话人和时间；Markdown 可追到文件名和段落/字符位置。

若模型从“服务很好”推断“五年维保”，但找不到支持“五年”的原文，输出只能标为`MODEL_SUGGESTION`，不得进入可确认的事实候选或发布批次。企业人员可补充明确原话，形成有来源的新提交，再提取候选。可定位原文不表示内容已为事实：候选仍需本企业有确认权限的人采纳，并由管理员发布版本。

## 来源改版与发布

新修订不会自动覆盖旧候选或已发布本体。抽取结果对照同一`source_id`的旧修订，若新文明确把“超过 500 万元”改为“超过 800 万元”，生成带`proposed_replaces`引用的候选，并列显示新旧原文、适用期和已引用该旧规则的已发布内容。仅因新版**未提及**一条旧内容，不自动推定该内容已废止。

审核人可采纳、拒绝或暂缓候选；互斥内容按现有冲突规则解决。采纳替代候选时，还须明确旧内容对新事项的终止生效时间及新内容开始时间；新候选引用的其他候选须在发布前满足依赖闭包。分类树新节点先发布，引用它的业务本体内容后发布，见[企业候选审核与发布规则](../ontology/publication-rules-v0.md)。企业管理员发布新的完整不可改本体版本或独立的分类树版本后，后续新事项使用新版；在办与历史事项保留启动时版本。旧资料修订、旧候选、旧发布版本和替代关系仍可查询审计。来源缺失的模型建议既不进入批次，也不触发旧事实停用。

## 最小验收例

1. 输入“采购经理负责发布采购；超过 500 万元需采购经理、采购总监、CEO 审批”，返回职位、职责、流程与约束的分条候选，每条可回到原文；未经确认发布，Agent 的正式本体查询仍看不到这些候选。
2. 同一资料的新修订写“超过 800 万元”，返回拟替代 500 万元规则的候选；旧采购仍按原版本解释，新采购只在新版本发布后采用 800 万元规则。
3. 输入“我们销售笔记本，并在上海提供五年维保”，区分乙方分类树节点候选、供应能力候选和地域/维保事实候选；输入“服务很好”不得产生“五年维保”事实候选。
