# RDF 词汇与 SHACL 发布校验（设计稿）

状态：首版数据规格，尚未实现。决策见[词汇与校验票据](../issues/36-define-rdf-vocabulary-and-shacl-boundary.md)。[W3C OWL 2](https://www.w3.org/TR/owl-syntax/)区分类、属性和个体；[W3C SHACL](https://www.w3.org/TR/shacl/)用于用形状图验证数据图，[Jena SHACL](https://jena.apache.org/documentation/shacl/)提供实现。

## 五种候选怎样发布

| 抽取候选 | 发布后的 RDF 表示 | 例子与边界 |
| --- | --- | --- |
| `Class` | 有稳定 IRI 的 `owl:Class`，有名称与定义 | `职位`类；企业专属类不改写通用基线类的含义 |
| `Property` | 有稳定 IRI 的 `rdf:Property`；明确连接对象或字面值时分别标为 `owl:ObjectProperty` 或 `owl:DatatypeProperty` | `直接上级`是职位到职位的谓词**定义**；改名为“直属上级”而含义不变时沿用 IRI |
| `Relation` | 对具体主体、谓词、客体的可引用 `rdf:Statement`；带范围的关系按[陈述模型](./rdf-claim-provenance-v0.md)附范围、时间和来源，不另断言无范围直接三元组 | “甲公司的采购经理职位，直接上级是采购总监职位”是一条**陈述**，与谓词定义分开 |
| `Constraint` | 企业词汇中的业务规则资源，例如 `EnterpriseConstraintRule`；保存原文、适用范围、时间和来源 | “餐标不得超过 200 元/人”是业务约束；其数值上限不变成首版 SHACL 形状 |
| `Instance` | 有稳定 IRI、通过 `rdf:type` 指向已发布类或同批采纳类的具体对象 | 甲公司“采购经理”职位实例；担任此职位的 A、B 是另外的人员实例与任职关系 |

五种类型只给 LLM 候选一个可审核的落点。候选中的定义和实例要分别确认；品类树节点及唯一父节点关系归**分类树版本**，不因候选类型为 `Instance` 或 `Relation` 就混进业务本体版本。业务关系采用陈述 ID，API 中一条关系仍算一跳。

## IRI 与版本

- 对外使用平台长期控制的 HTTPS 命名空间，形式示例为 `https://<owned-domain>/id/company/<opaque-company-id>/<kind>/<opaque-id>`；通用基线术语有独立平台路径。实际域名必须在首次发布 RDF/OWL 文件或 SPARQL 服务之前确定。
- IRI 不包含中文名称、部门名称、当前版本号或可变分类路径；名称变化不换 IRI。同一语义对象跨不可改快照沿用 IRI；含义改变须新建 IRI，保留旧版与替代关系。企业采用基线定义时引用基线 IRI；企业不同含义的扩展使用企业 IRI，注明对应关系。
- LLM 提议先有候选 ID；人工采纳后分配正式 IRI，管理员发布前不对普通 Agent 可见。来源片段与陈述分别有 IRI；同一事实可关联多份独立来源。

## 发布前校验分工

| 执行者 | 阻止发布的检查 | 不负责的事情 |
| --- | --- | --- |
| 平台版本化的基础 SHACL 形状 | 必需名称/定义/规则原文；陈述的主体、谓词、客体各恰有一个且种类正确；至少有一条来源引用；已填写时间和范围字段的 RDF 类型、数量与格式；业务规则有明确适用范围和生效依据 | 判断餐标 200 元是否合理，或本次采购是否超过餐标 |
| 本工程程序 | 候选已处理、来源及其他引用的目标实际存在、跨图/跨数据集引用闭包、租户及权限、分类树唯一父节点与先发布顺序、同一适用期冲突、版本切换与事务 | 代替 LLM 判断采购条件是否满足 |
| 已发布知识包与 LLM | 本次条件、企业硬约束的适用性和业务满足情况；证据不足时返回待补/待澄清，并保留理由和版本 | 发布候选、越过 SHACL 失败或补造缺失本体关系 |

基础形状在平台受控位置维护，并记录验证时使用的形状版本。企业可以通过候选与人工发布扩展类、属性、实例和业务规则，不能编辑基础形状。**对拟发布的完整企业快照验证**，通过后才在该企业 TDB2 数据集内发布新版本；只验本次变更可能漏掉其与旧内容组合后的错误。返回的 SHACL 报告应定位条目 IRI、字段路径和失败原因，供管理员修正。

普通事实的范围或生效期原文未说明时，不能因为缺字段就推定“所有地区、永久有效”；审核界面须明确标记未知，业务判定按未知处理。已填写的范围与时间需通过结构校验；要求自动生效的企业硬约束则必须明确适用范围和生效依据。事实间是否矛盾、文本是否真实以及乙方本次诚信声明是否可信，不是 SHACL 结构验证结论。
