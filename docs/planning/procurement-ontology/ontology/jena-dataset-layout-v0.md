# Jena/TDB2 多企业数据集与版本图布局（设计稿）

状态：产品架构规格，尚未实现。决策见[企业数据集布局票据](../issues/34-define-jena-tenant-dataset-and-version-layout.md)。

## 数据集与图

| 范围 | 保存内容 | 对外可见性 |
| --- | --- | --- |
| 平台数据集 | 通用业务本体基线、分类模板的候选和发布版本 | 由平台管理员维护；企业只通过已采用的固定版本使用 |
| 每企业独立 TDB2 数据集 | 本企业业务本体及分类树；各自的候选批次、当前发布内容和历史完整快照；来源与判定审计 | 经本工程 API/MCP 授权读取；不凭数据集地址直接取得权限 |
| 企业候选命名图 | 未分批待审内容和当前待发布批次 | 仅本企业有审核权限的人通过治理接口可见；Agent 普通查询不可见 |
| 企业发布版本命名图 | 业务本体、分类树各自不可改的完整快照；保留版本、来源与采用的基线版本 | 内部按版本用于在办判定、历史审计；普通 Agent 不任意搜索旧版 |
| 企业当前读取视图 | 两个稳定命名图，分别保存当前业务本体和当前分类树的副本 | 普通 Agent 只看到有权访问的最新版；后期只读 SPARQL 也仅开放被授权图 |

这里的“独立数据集”是企业数据的存储及查询边界，可以由同一个 Fuseki 进程托管，不等于每家公司必须单独部署服务器。Fuseki 官方支持一个服务承载多个数据集，并可分别配置数据服务和只读端点。[多数据集](https://jena.apache.org/documentation/fuseki2/fuseki-embedded.html)、[服务配置](https://jena.apache.org/documentation/fuseki2/fuseki-configuration.html)。

## 发布与读取

1. 企业管理员发布分类树或业务本体批次前，系统完成既定的候选状态、引用闭包、冲突和结构校验。新分类节点仍须先于引用它的知识包或能力发布。
2. 发布在该企业数据集的一次 TDB2 写事务中建立新完整版本图、更新相应当前版本指针和稳定的当前读取图、记下发布人及时间；失败时保留旧当前版本。**完整版本图不可改；当前读取图是可替换的副本，不能当作历史快照。** 两类发布各自独立，不把分类树与业务本体强行合成一个版本。TDB2 提供事务基础，但批次确认和不可变约束由应用实现。[TDB2 事务](https://jena.apache.org/documentation/tdb/tdb_transactions.html)。
3. 普通搜索与按 ID 读取只看当前发布内容；若两次读取之间发生发布，返回版本变化而非混用。采购项启动时绑定的旧业务本体和分类树版本由内部判定服务读取；历史解释使用具体审计引用。
4. 甲乙匹配一次针对一个乙方和本次采购的全部采购项。服务分别读取获准使用的甲方规则和乙方能力、事实，再结合本次临时声明判定；跨企业响应只返回本次授权披露的路径、片段和判断依据。平台基线采用后固定在企业版本中，平台升级不自动改变企业快照。

版本图中的带范围事实使用[可引用的 RDF 陈述](./rdf-claim-provenance-v0.md)，来源片段保留独立引用和文档版本。当前读取图可暴露获授权的陈述及来源引用；来源原文所在受限图须单独授权，不能因为能查陈述就能读整份资料。

## 权限与验收边界

- 首版 Fuseki 不向外部 Agent 开放直连；外部仅调用业务 JSON API/MCP。后期 SPARQL 设只读服务并按企业与图授权。Fuseki 图级 ACL 当前适用于只读数据集；项目级逐条披露仍由业务 API 裁剪。[Fuseki 访问控制](https://jena.apache.org/documentation/fuseki2/fuseki-data-access-control.html)。
- 验收至少覆盖：甲方身份不能查询乙方私有图；普通查询看不到候选与旧版；发布失败不切换当前版本；在办判定仍可取旧快照；新分类树与业务本体独立发布；平台基线更新不改变既有企业数据集。
- 未确定数据规模与查询延迟，需用试点数据检验当前读取图复制成本、完整快照的存储增长和 TDB2 单写事务吞吐。
