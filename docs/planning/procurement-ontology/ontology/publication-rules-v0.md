# 企业候选审核与发布规则（设计稿）

状态：产品规则规格，尚未实现；不指定页面或数据库。决策见[候选依赖与发布顺序票据](../issues/26-define-candidate-dependencies-and-publication-order.md)，批次和权限边界见[企业本体发布票据](../issues/13-define-enterprise-ontology-publication.md)。

## 审核中的依赖

候选可逐项采纳、拒绝或移出本批暂缓。采纳一条候选**不会自动采纳**它引用的候选。发布前对本批所有采纳内容检查引用闭包：每个被引用的类、属性、关系、实例或规则，必须已在可采用的已发布版本中，或同属本批已采纳内容。被拒绝、暂缓或仍未确认的依赖项不能支撑本批发布；界面列出受阻候选和缺少的引用，供审核人补采纳、改引用、拒绝或移出本批。发布校验还包含现有的来源、结构和同一适用期事实冲突检查。

结构部分使用平台维护的[基础 SHACL 形状](./rdf-vocabulary-shacl-v0.md)验证拟发布的完整快照；跨数据集引用、权限、分类树发布顺序和事实冲突仍由本工程程序校验。形状失败或程序校验失败均阻止发布，并向管理员返回具体对象与原因。

## 分类树先于业务本体

采购负责类、一级品类、二级品类及其父子关系归企业分类树批次。知识包、乙方供应能力等业务本体内容如果引用**新节点**，须先由企业管理员发布包含该节点的分类树版本，再发布业务本体批次。业务本体发布时记录所引用的分类节点 ID 和已发布树版本；仍指向未发布或已拒绝节点的候选不能发布。两类批次分别审核、分别编号，不要求同步成一个版本。

两次发布之间，新节点可已存在而知识包或能力暂缺。甲方按该节点查询时如实返回知识包缺失；乙方在能力尚未发布并确认可供匹配前，不进入常规供应商检索。正在进行的项目仍可按既定规则使用项目临时能力。旧采购和旧本体快照保留它们原先引用的分类版本；之后树的升级仍需按影响评估处理。

## 规则替代与时间

`proposed_replaces`只是新候选对旧内容的提议，不是自动失效指令。审核人采纳替代候选时，须同时确认旧规则在**新本体版本面向新事项**的终止生效时间，以及新规则的开始生效时间；发布前检查两者在同一适用范围内没有未处理的重叠冲突。若缺时间或冲突未解决，阻止发布并指出具体规则。

旧版完整快照不可改，在办与历史事项仍按启动时绑定的旧版本解释。新版本中的终止时间只决定该新版及后续版本如何处理**新启动事项**，不回写已启动事项的旧规则。若新资料仅省略旧规则，不能自行生成终止时间或停用操作。

## 最小验收例

1. 乙方“供应笔记本”能力已采纳，但所引用的“笔记本电脑”节点仍是分类树候选：业务本体发布校验失败；树节点先发布后，同一能力才可发布。发布能力时管理员还须确认是否打开可供采购匹配标记。
2. 已采纳的“五年维保”事实引用尚未确认的能力：事实不能单独发布；采纳该能力到本批或改成有效引用后重试。
3. 甲方新版审批阈值 800 万元拟替代旧 500 万元规则：审核人明确旧规则终止和新规则开始时间后才能发布；旧采购仍由旧本体版本解释。
