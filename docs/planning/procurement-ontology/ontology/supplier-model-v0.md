# 乙方能力、事实与本次声明：最小本体结构（设计稿）

状态：产品数据结构规格，尚未实现；本文件描述逻辑模型，首版权威库见[Jena 选型依据](../research/jena-fuseki-authoritative-store-v0.md)，事实表示见[RDF 陈述与来源设计稿](./rdf-claim-provenance-v0.md)。决策见[乙方结构票据](../issues/24-define-supplier-ontology-structure.md)。

## 四种不同的数据

| 对象 | 最少内容 | 用途与边界 |
| --- | --- | --- |
| `SupplierCapability` | 稳定 ID、乙方 ID、所引用的乙方二级品类节点及树版本、可提供内容的说明、关联事实 ID、`可供采购匹配`标记、本体版本 | 已确认发布的供应能力。分类节点本身不能证明乙方有此能力；只有管理员在发布时确认打开检索标记，才进入常规跨企业供应商查找。一个乙方可有多条跨采购负责类能力。 |
| `SupplierFact` | 稳定 ID、原文与结构化摘要、来源、适用范围、生效/到期时间、关联能力 ID、本体版本 | 已确认发布的资格、品牌、团队、案例或服务承诺。事实独立于能力，可被多条能力引用；引用不扩大事实本来的品牌、地域、品类、项目或时间范围。 |
| `ProjectDeclaration` | 外部采购项目与条件 ID、乙方原话、说话人或服务身份、时间、声明的品类路径或条件、披露授权引用 | 本次诚信声明，由外部系统随判定请求传入。可在本项目自检或甲方重判中使用；本工程在判定审计中保留来源引用，并自动去重生成乙方待确认候选。它不是已发布本体事实。 |
| `TemporaryCapability` | 本项目 ID、乙方原话、临时完整三级路径及各级描述、关联声明、来源 | 乙方已发布本体尚无相应能力时，本项目用于品类初筛的临时能力。即使乙方树尚无该二级节点，也可用原话生成临时路径；新分类节点与能力分别进入对应待确认队列。发布前不参与常规供应商检索。 |

乙方自己的分类树始终是`采购负责类 → 一级品类 → 二级品类`，各节点只有一个父节点。`TemporaryCapability`的临时路径不是已发布树节点，不能伪装成树版本中的节点 ID。甲方树和乙方树各自独立；两边品类在一次采购中按完整路径与描述作语义初筛，之后逐条件判断。

## 适用范围、发布与检索

- 事实标明企业、品牌、地域、二级品类或项目等适用范围，并标明生效和到期时间。判定时先检查事实是否适用于本项目与判定时间；关联某能力不消除事实限制。
- 乙方本次承诺即使与旧版已发布事实相反，仍可按本次诚信声明参与判断；返回冲突和两边来源，旧事实不被直接改写。
- 本工程从新能力或声明自动生成待确认候选，保留本次项目来源、原话、身份和时间。乙方有确认权限的人处理候选，管理员发布新的不可改本体版本。对**可复用的能力或服务承诺**，发布后的适用范围默认是通用的，供后续适用采购读取；管理员可明确限定品牌、地域、品类、时间或项目。原始材料明确限定“仅限项目 P”时，发布后仍限 P，不能被默认通用规则扩大。
- 能力发布和进入常规检索是两个明确判断。发布新能力时，管理员须同时确认`可供采购匹配`标记；未打开仍是已发布能力，但不进入常规跨企业查找。本项目的临时声明不自动打开该标记。
- 新能力引用的乙方二级品类若也来自待确认候选，须先发布含该节点的企业分类树版本，再发布能力的业务本体版本；能力所引用的事实或其他定义须已发布或在同批采纳。发布校验规则见[候选审核与发布规则](./publication-rules-v0.md)。
- 已发布但未标为可检索的能力，以及尚未发布的`TemporaryCapability`，只有在乙方针对**当前项目**主动声明并获授权披露后，才可作为该项目的品类初筛输入。当前项目判定必须标明`TEMPORARY_DECLARATION`来源；后续其他项目不能复用它作为已发布能力。

## 以电脑采购为例

乙方已发布树有电脑与工服，但已发布能力只有工服。乙方收到电脑需求后声明“本项目可以供电脑，提供五年维保”。本工程可为本项目建立临时电脑能力，拿其完整三级路径和甲方路径作匹配；五年维保作为逐条件诚信声明参与判断。旧本体的三年维保仍返回冲突提示。新电脑能力与五年维保分别成为乙方待确认候选。

如果管理员发布电脑能力并打开检索标记，未来采购才能在常规查找中发现该能力。管理员确认发布五年维保为可复用承诺后，默认可供未来适用采购读取，同时保留“最初源于项目 P”的来源记录。如果原话或原厂文件明确只授权项目 P，事实仍限 P；以后采购不能把该授权当作通用授权。

## 与外部接口的关系

`evaluate_supplier_admission`一次评估一个乙方的全部相关采购项。请求可带当前项目的临时能力路径及逐条件声明，本工程结合乙方已发布本体判断，返回品类三态、逐条件结论、来源类型、冲突、候选和审计引用。外部系统保存采购需求、乙方响应及正式入围状态；本工程不把`TemporaryCapability`写进已发布树，也不接管业务台账。
