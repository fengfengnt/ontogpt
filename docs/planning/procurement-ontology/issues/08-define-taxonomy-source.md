## Question

平台通用的 `采购负责类 → 一级品类 → 二级品类` 树以自建分类为主、引用外部标准为主，还是自建并映射外部标准？谁有权新增、移动、停用节点，如何保持已有采购需求与乙方能力记录可解释？若选择外部分类，需先调查映射可行性与使用许可。

## Answer

- `采购负责类 → 一级品类 → 二级品类` 分类树由平台自建，初版定义由用户提供。平台通用树是可版本化的**企业模板**；甲方和乙方各自采用模板形成、维护本企业的严格三级分类树。平台模板与企业树的节点不是跨企业匹配时必须共享的同一 ID。分类模板可先于从试点提炼的通用业务本体存在。
- 平台系统管理员维护通用模板，并创建企业与企业管理员。企业中同时具有分类维护菜单权限和当前公司权限的人，可增删改本企业树中来自模板的本地节点及本企业新增节点；本地修改进入企业树的独立待发布批次，由企业管理员发布为新版本，不回写平台模板，见[界定企业本体版本的确认与发布](./13-define-enterprise-ontology-publication.md)。平台模板的新版本不自动改写已落地企业树，采用新版的影响与迁移由[界定通用基线升级的影响评估与迁移](./09-define-baseline-upgrade.md)处理。
- 采购项引用甲方树中的二级品类；乙方已确认能力引用乙方树中的二级品类。系统根据完整三级路径各级的名称、定义和说明文字，自动判断两条路径是否语义一致，可使用 LLM；同名不能单独证明匹配，也不要求人逐条确认品类等价。品类自动匹配与具体必须项的机器判定或甲方人工核验是不同判定，见[供应商 Agent 准入契约](./16-define-supplier-agent-shortlist-flow.md)。
- 自动语义判断不明确时标为“待判定”，暂不算品类覆盖，因而暂不初步入围。企业可补充节点描述；下一次甲方需求匹配或明确重算时使用新内容。保留比较输入、结果、理由及所用模型或规则版本，供双方解释和有权限的专家审计。具体判定与试运行统计见[界定跨企业品类语义匹配的判定与验收](./11-define-category-semantic-matching.md)。
- 节点改名时保留身份并记录版本；移动或停用形成新版本。已有采购项和乙方能力按引用时的节点版本及完整路径解释；已被引用的节点不物理删除。平台模板删除节点也只影响之后的模板版本，不改写既有企业树和历史记录。
