# 界定通用基线与企业扩展的版本关系

Type: grilling
Status: resolved
Blocked by: 02

## Related

- [界定采购负责类、品类、服务能力与甲乙方本体边界](./02-define-domain-vocabulary.md)

## Question

哪些概念和关系属于平台通用基线，哪些属于企业扩展或企业实例？企业如何引用、重命名、扩展或拒绝通用定义；通用基线升级时如何保持企业既有解释和匹配结果可追溯？

## Answer

- 首版先选一家甲方和一家乙方落地。试点企业用自然语言概述企业情况、采购或供应过程及主要工作内容，先生成**基础业务本体候选**，经企业管理员确认后成为各自的企业本体；这一步不要求已有通用业务基线，也不预设先按成熟业务 schema 抽取。后续再依据已确认的 schema 从自然语言或 Markdown 抽取更多内容。技术层面的候选表示格式不等于预先制定通用业务本体。
- 试点企业本体可同时包含企业专属的类、属性、关系、约束等**定义**，以及职位、人员、采购项、供应能力等**实例**。“通用基线是类定义、企业本体是类实例”仅是复用关系的类比，不限制企业新增本地定义。
- 从首家甲方和首家乙方的已确认内容总结出首版通用基线，供后续企业快速落地；共性候选的具体提升门槛、审核和脱敏规则由[界定企业共性提升为通用本体的规则](./06-define-common-knowledge-promotion.md)决定。
- 后续企业固定引用自己采用的通用基线版本，并保留企业专属定义和实例。平台发布新版不会自动改变已落地企业；企业管理员查看影响并主动确认后才升级。既有业务记录需能追溯当时使用的基线版本。
- 企业不能直接改写所引用通用术语的原意；可增加本企业别名，或新建本企业术语并标明与通用术语的对应关系。局部定义不会自动进入通用基线。
