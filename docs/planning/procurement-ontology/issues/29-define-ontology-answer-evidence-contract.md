## Question

通用问答检索返回相关条目与最多三跳的真实路径之后，本工程是否还给“足以支持回答”的结构化结论？没有证据、找到反向事实或出现冲突时，应怎样告知外部 Agent，防止它把相关路径说成采购资格事实？

## Established boundary

- 本工程供外部 Agent 通过 API/MCP 查询和判定；外部系统负责聊天界面、对话编排和正式业务状态。
- 通用搜索只查有权可见的最新版已发布内容；结果相关性和路径可达性均不等于条件满足。每条路径有节点、关系、类型、来源与版本。
- 具体采购入围由专用`evaluate_supplier_admission`判断，乙方本次逐条件声明可在该项目中优先于旧本体事实，但冲突须显示；通用本体查询不应把这条项目声明误记为已发布事实。
- 查询“供应商注册资本”时，品牌所属公司的注册资本不能作为供应商事实。判断须核对问题主体与路径末端事实主体。

## 用于检验选择的例子

甲方 Agent 问“这家供应商是否具备五年维保？”检索到乙方已发布的三年维保事实，还收到该乙方针对本项目的“五年维保”声明。通用搜索和本次准入判定的输入范围不同，不能悄悄只展示其中一个。

另一个问题是“华硕品牌是否在本次允许品牌范围内？”若找到明确允许关系，可给证据路径；若只找到了华硕与华硕公司关系，不能把它当作允许关系。完全没找到品牌关系时，也不能自动断言“华硕不允许”。

## Decision

- 普通`search_ontology_items`只负责发现相关条目和真实关系路径；针对明确命题另设只读`assess_ontology_claim`，由本工程返回`支持 / 反驳 / 依据不足 / 冲突`、实际证据路径及判定理由。外部 Agent 负责组织聊天回复，采购准入仍调用`evaluate_supplier_admission`。
- 只有同一主体、关系含义、适用范围和有效期内的已发布内容才能支持或反驳该命题。`反驳`需要明确的反向事实；没有查到允许关系、命中无关路径或检索上限内证据不足时返回`依据不足`，不能把缺失解释为禁止。支持与反向内容同时有效时返回`冲突`并列出双方来源。
- 通用核验只用调用方有权查看的最新版已发布本体，不纳入本次采购声明、待确认候选和草案。项目判定接口另行展示已发布事实与本次声明的冲突，并按已确定的本次声明优先规则判定。若问题依赖本次采购的临时条件，通用核验不代替项目判定。
- 结果保留本体/分类树、检索与模型版本及来源引用；LLM 可判断命题与已检出证据的语义关系，但不能补造图中没有的边，也不能把品牌所属公司的属性转成供应商属性。详细契约见[Agent 本体读取接口设计稿](../api/ontology-read-v0.md)。
