# 界定采购职能、职责与工作流程的建模范围

Type: grilling
Status: resolved
Blocked by: 01

## Related

- [界定首版采购需求与供应商能力的业务契约](./01-define-matching-business-contract.md)

## Question

采购总监、采购经理等是通用岗位模板、企业内实际岗位、人员任职，还是流程中的审批角色？首版需要描述哪些职责、任务、交接与审批关系；企业流程与通用流程不一致时如何表达？

## Answer

- 首版按**每家甲方企业**定义职位。职位包含名称、职责和业务权限；人员通过任职关联职位，同一职位可有多人。“直接上级”连接职位与上级职位，不连接具体人员。甲、乙、丙公司可用各自职位划分采购发布、筛选、供应商选定及到货验收职责。
- 审批流程由企业确认，可根据采购金额等条件指定多级审批职位及顺序。一个步骤指定一个职位；该职位任一任职人员完成即可，并记录实际操作人。例如金额大于 500 万的流程可依次由采购经理、采购总监和 CEO 审批。
- 职位的业务动作和审批权限与账户登录、应用菜单权限分开管理。企业确认的流程优先于通用流程；首版尚无平台通用基线，以试点企业自己确认的流程为准。
- 若企业已发布自动入围政策且本次采购在外部系统显式启用，客观必须项机器通过后可走自动邀请分支；外部系统记录执行服务身份、授权记录和政策版本，不把自动动作伪记为某位人员审批。主观项及其他审批步骤仍按企业流程处理，见[供应商 Agent 准入契约](./16-define-supplier-agent-shortlist-flow.md)。
- 企业修改已确认流程后，在办采购继续使用启动时确认的流程版本；新启动的采购使用新版。审批记录应保留实际操作人和对应流程版本，以便追溯。
