## Question

在 TDB2 中，如何保存一条带品牌、地域、有效期和多份原文来源的企业事实，使 SPARQL、业务 API 和历史审计不会把有范围的事实误读成无条件成立？同一事实被两份资料支持时怎样计数？

## Decision

- 首版以有稳定 IRI 的陈述资源表示已发布业务事实和关系，保存主体、谓词、客体或值、肯定/否定、适用范围、有效期及发布版本。使用标准 `rdf:Statement` 与 `rdf:subject / rdf:predicate / rdf:object` 描述陈述，范围和时间用本产品词汇明确限定；来源片段各有独立引用。
- **含限定范围的业务事实不同时写成无条件的直接三元组。** RDF 的重述不蕴涵被描述的三元组，业务 API 和 SPARQL 查询必须核对陈述的适用范围与时间；图上的业务连线是该陈述的展示投影，不是另一份权威事实。
- 两份资料的主体、关系、值、极性、适用范围和有效期确实相同时，保留**一条事实，关联两份独立来源**。若其中任一语义字段不同，则分别建事实；新资料改正旧说法时不覆盖旧版快照。
- 已发布版本图保留当时的事实和来源引用，来源片段保留独立身份与文档版本。后来的新来源可在新快照中挂到同一事实 IRI，旧快照仍可复现。候选、本次临时声明和已发布事实继续分开。
- 这是 RDF 文件交换和 SPARQL 可查询的首版数据表示，不承诺外部 OWL 推理器从自定义的范围属性自动推导事实；具体词汇 IRI、SHACL 形状和往返导入测试待实现时验证。
