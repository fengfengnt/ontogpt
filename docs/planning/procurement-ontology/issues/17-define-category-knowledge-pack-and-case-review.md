## Question

甲方每个二级品类的“知识包”如何组织需求字段、供应条件和证据判定；LLM 的品类与证据高阈值匹配分别在运行时和案例验收中承担什么作用；人工对案例入围结果的复核如何与本工程只返回数据、外部系统处理错误的边界保持一致？

## Answer

- 每个采购项依其二级品类使用知识包；结合采购人员给出的数量、预算等本次数据，判断乙方是否满足入围条件。
- LLM 品类匹配只作初步筛选，例如采购电脑时先找可能卖电脑的乙方，不能据品类匹配直接断定入围。
- 在案例中，双方品类和证据可由 LLM 判断是否达到高阈值匹配；试点和回归案例先由人写下每个“采购项 × 乙方”的预期入围结论及理由，再运行本工程并由人对照复核。线上每笔采购不因此增加人工审核步骤，仍可按已授权规则自动入围。
- LLM 的证据高相关匹配只找出候选证据；是否满足必须项仍按知识包规则核验具体事实，不能仅凭相似度判通过。
- 本工程对高相关证据返回受权限约束的原文片段、来源、关联的知识包条件和相关性理由，供具体事实核验、案例复核及审计。
- 知识包是需求采集字段、供应商条件、证据要求和判定规则的集合。本次数量、预算等实际值由外部系统传入。
- 不确定判定和事后发现的错误由外部系统负责处理；本工程基于甲乙双方各自的本体数据返回判定结果。
- 不设整体数值通过门槛。若某案例被判“符合自动入围条件”，而人工预期认为不应入围，须修正相关知识包或判定规则并重测该案例；该品类完成此项前不启用自动入围。案例复核及启用决定由外部系统承载，本工程提供可追溯的判定与版本。
