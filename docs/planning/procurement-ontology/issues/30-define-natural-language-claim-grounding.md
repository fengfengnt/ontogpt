## Question

外部 Agent 用自然语言调用通用命题核验时，本工程如何确定命题的主体、关系、客体和适用范围？遇到多个同名主体、模糊关系或问题依赖本次采购临时条件时，怎样如实返回查询结果而不误判？

## Established boundary

- `search_ontology_items`发现相关条目，`get_ontology_item`按 ID 读取一跳详情，`assess_ontology_claim`对明确命题返回支持、反驳、依据不足或冲突及真实证据路径。
- 普通核验只看有权查看的最新版已发布本体；本次采购声明、草案和临时条件由专用采购判定接口处理。
- 问句中的主体须与证据路径所述主体一致；关联到品牌厂商不等于关联到供应商。
- 外部 Agent 不一定预先知道条目 ID，且它负责聊天补问与对话编排。

## 用于检验选择的例子

- “华硕是否在允许品牌范围？”可能指甲方电脑采购知识包中的品牌规则，也可能指某次采购新增的品牌限制。
- “这家供应商有五年维保吗？”若当前上下文同时出现两家供应商，不能凭任意一家已发布事实给出支持结论。
- “华硕公司注册资本够吗？”如果没有“够”的金额门槛，不能把找到注册资本数值当作命题已成立。

## Decision

- `assess_ontology_claim`接受自然语言问句，主体 ID 可选；本工程在调用方获授权的已发布本体中识别主体、关系、客体和适用范围，并回显解析出的 ID 与命题。若同名或指代对应多个主体，返回`依据不足`、候选主体 ID 和需要澄清的歧义，不替外部 Agent 选定。
- 关系含义或比较门槛不明确时，返回`依据不足`及具体缺少的关系解释、比较值或单位，供外部 Agent 自行决定是否补问。不能按“最可能”的解释直接给支持或反驳。
- 普通核验不持有本次采购的临时条件。“本次采购是否允许华硕”一类问题若依赖这些条件，返回`依据不足`，说明当前已发布本体中没有足以回答**本次**问题的数据；不把企业通用规则冒充本次条件，也不规定 Agent 后续必须调用哪个接口。外部 Agent 可以据此直接回答“查不到”，后续行为由其自身决定。
- 上述不足结果仍受权限过滤；返回可披露的候选和缺失原因，不泄露无权查看的主体、规则或其存在性。接口详情见[Agent 本体读取接口设计稿](../api/ontology-read-v0.md)。
