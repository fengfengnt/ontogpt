## Question

在 Jena/TDB2 中，一家甲方和一家乙方的候选、分类树、已发布本体及历史版本怎样隔离，才能支持企业权限、独立发布和跨企业准入判定？

## Decision

- **每家公司使用独立的 TDB2 数据集**；平台通用基线使用平台数据集。一个 Fuseki 服务可承载多个数据集，但数据集 URL 不是授权凭据，必须由本工程验证身份和当前企业。
- 企业数据集内以命名图区分待审业务本体批次、待审分类树批次、不可改的已发布业务本体版本和分类树版本，以及内部来源和审计记录。业务本体与分类树各自维护当前版本指针，按既定规则独立发布。
- 对普通 Agent 的查询只返回当前已发布版本。为后期只读 SPARQL，提供仅含当前可披露内容的受控读取视图；候选、来源全文和历史版本不得因直接查询数据集而泄露。在办判定和历史审计由内部服务按绑定版本读取。
- 跨甲乙匹配由本工程分别读取甲方和乙方数据集，在业务服务内结合本次输入判定，再按授权裁剪结果；不提供可任意跨企业查询的 SPARQL 入口。企业内本体快照包含其采用的固定通用基线版本，不在查询时悄悄切换平台最新版。
- 发布操作必须在该企业数据集的一次受控写事务中形成新快照并切换当前读取视图；失败时当前版本不变。版本图保持不可改，当前视图或指针可以切换。技术实现和租户越权仍需试点验证。
