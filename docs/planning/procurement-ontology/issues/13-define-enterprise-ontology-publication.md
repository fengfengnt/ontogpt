# 界定企业本体版本的确认与发布

Type: grilling
Status: resolved
Blocked by: 04, 09

## Question

用户提出“每个本体候选人工确认，全部确认后以企业本体新版本发布”。“全部”指一次导入批次还是整个企业的所有待审候选？候选确认后何时可被业务使用，版本由谁发布；已确认本体内容在图上编辑立即生效的既有规则如何与统一发布保持一致？通用基线升级后的发布细则可待相应升级场景再定。

## Answer

- “全部确认”以**一次明确的企业业务本体变更批次**为范围，不要求该企业所有候选同时处理。每家企业同时最多有一个待发布的业务本体批次。新提取候选先进入未分批待审队列，企业管理员可将其加入当前批次，或待当前批次发布后再开下一批。
- 批次内每条候选须由有本企业确认权限的人明确标为“确认采纳”或“拒绝”；冲突项二选一后另一项拒绝。暂缓处理的候选移出本批，回到未分批待审队列。已确认采纳的内容只进入待发布版本，业务流程和 Agent 在发布前仍使用当前已发布版本。
- 有本企业确认权限的人在图上修改已确认的类、属性、关系或约束，保存即视为人工确认该修订，并放入当前待发布批次；无批次时开启一个批次。无须再对同一修订点击确认。保存本身不改变已发布版本。这取代[第 04 项](./04-define-company-knowledge-intake.md)原定的“图上编辑后立即生效”。编辑人、编辑时间和与原始来源不同的人工修订来源均留档。
- 本企业管理员查看本批采纳内容及相对现行版本的差异，点击发布。发布前系统校验类、属性、关系和约束的引用完整性，并检查同一适用期内互斥的事实已解决；未通过则列出问题并阻止发布。整批一次发布为不可改的完整企业本体快照，记录版本、来源批次、差异、发布人和时间；拒绝项不进入快照。
- 发布后，新启动的采购及 Agent 查询使用新版本；历史和在办采购、竞标及履约事项仍按启动时引用的本体版本解释。旧版本不被直接修改。企业分类树与业务本体分别版本化：本地树节点修改进入树的独立待发布批次，由企业管理员独立发布，既有引用保留原路径和版本。
- 通用基线与通用分类模板的升级仍遵循[第 09 项](./09-define-baseline-upgrade.md)的影响预览、冲突选择和企业管理员确认；本项确定企业本地变更的确认与发布规则。
