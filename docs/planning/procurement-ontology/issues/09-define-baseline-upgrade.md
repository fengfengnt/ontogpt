# 界定通用基线升级的影响评估与迁移

Type: grilling
Status: resolved
Blocked by: 05, 08

## Related

## Question

企业管理员主动采用新版通用基线时，系统应如何列出新增、修改、停用的定义及其对企业专属定义、分类引用和既有采购/供应记录的影响？冲突项如何选择，何时生效，怎样保留旧版本下的历史解释？

## Answer

- 平台的**通用业务本体基线**与**通用分类模板**分别发布和编号，企业可分别选择目标版本升级；任一新版发布都不自动改变已落地企业。
- 升级前向企业管理员展示目标版本相对企业当前采用版本的新增、修改、移动和停用内容，以及受影响的企业专属定义、职位、流程、分类节点、采购项和乙方能力记录。分类模板采用差异合并：本地未改的节点可随新版更新；本地已改的节点逐项选择保留本地内容或采用新版，不整棵覆盖企业树。
- 通用业务定义与企业专属定义冲突，或新版停用企业仍在使用的定义时，逐项选择采用新版并迁移将来使用的引用，或保留旧含义为企业专属定义。未解决完冲突，不能启用该目标版本；不自动以新版替换企业已确认的本地含义。
- 企业管理员看完差异与影响、处理全部冲突后点击确认，系统形成新的企业本体版本或企业分类树版本，立即供**新启动事项**使用，并记录目标版本、选择结果、确认人和确认时间。两个升级流程相互独立。
- 已启动的采购、竞标及履约事项和历史记录继续使用启动时的本体、分类及流程版本，并可查看当时的完整路径和定义。新版停用某二级品类后，旧记录保留原引用；若新事项仍需该品类，企业须选择保留为本地节点或改指替代节点，不能悄悄改写既有引用。
