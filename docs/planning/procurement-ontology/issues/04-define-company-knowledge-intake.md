# 界定企业资料到本体候选的采集与确认流程

Type: grilling
Status: resolved
Blocked by: 02

## Related

- [界定采购负责类、品类、服务能力与甲乙方本体边界](./02-define-domain-vocabulary.md)

## Question

甲乙方首次落地时，哪些资料或人工输入构成采购负责类、品类、能力、职责和流程的事实来源？如何保留出处、区分自动提议与事实确认、处理冲突，并由谁批准企业本体发布？

## Answer

- 首次落地先从企业自然语言概述生成基础业务本体候选；企业已有已确认 schema 后，再从自然语言输入或 Markdown 文档按 schema 提取类、属性、关系和约束。两阶段都逐项列为**本体候选**。拥有本企业管理员权限的人可逐项确认，或勾选批量确认；确认后进入本企业待发布的本体变更批次，发布后才供业务使用。首版不自动确认；批次发布规则见[界定企业本体版本的确认与发布](./13-define-enterprise-ontology-publication.md)。
- 每条候选及确认内容保留来源。自然语言记录原文、发送人和发送时间；Markdown 记录文件名、原文片段、段落位置及当次文件版本，原始文件保留在企业空间。
- 确认时并列展示同一适用期内互斥的候选或已确认内容，冲突项只能二选一；若涉及此前已确认内容，明确提示。不同生效期的规则可以共存，例如去年与今年的采购金额规则。批量操作先确认无冲突项，冲突项留待单独选择。
- 已确认内容可图形化展示，并可点击类节点或关系线编辑。拥有确认权限的人保存图上修改，即确认该修订并纳入待发布批次；**发布后才对新事项生效**，记录编辑人和编辑时间。原始文本来源仍保留，图上修改另记为人工编辑，不把旧原文当作修改后内容的直接证据。
- 企业本体中可同时存在本地定义和实例，分层决策见[界定通用基线与企业扩展的版本关系](./05-define-shared-baseline.md)。
