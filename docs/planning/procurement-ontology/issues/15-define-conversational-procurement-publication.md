## Question

采购员只说“我要采购 100 个电脑”时，本工程按本企业已发布本体返回怎样的品类候选、采集字段规则与适用流程，才能让外部采购 Agent 知道先问什么、何时字段已齐备、哪些值必须由采购员确认？本次具体取值和发布由外部系统负责；需界定按品类可复用规则与每采购项独立条件的边界，以及 API 返回结构和版本依据。

## Answer

- 外部采购 Agent 将采购员表述（如“我要采购 100 个电脑”）和当前企业身份交给本工程。本工程从该企业**最新已发布**分类树识别完整的`采购负责类 → 一级品类 → 二级品类`路径。若有多个可能的二级品类，返回候选路径、理由和“待确认”状态，由 Agent 请采购员选择；确定二级品类后才取该品类的规则。多品类需求仍按[第 01 项](./01-define-matching-business-contract.md)拆成多个采购项，各自查询规则。
- 每个企业二级品类可关联两组可复用业务规则：**采购需求采集字段**（如数量、型号、预算、交期）和**供应商条件模板**（如品牌、维保、SLA、必须项及评分细则）。这些规则属于企业本体，不把本次采购的具体条件写死在分类树节点上；本次采购项独立确定具体取值、门槛、权重和细则。规则包含必填性、数据类型、单位、允许范围、条件依赖和可用默认值，并返回各自的来源与版本。
- 原话提取值、模板默认值和采购员输入值分别标注来源；它们可供 Agent 预填或建议，但本次需求取值和供应商条件须由采购员确认。外部 Agent/业务系统持有多轮对话草案，每轮把当前选定品类、已填值及先前使用的本体/分类版本传入本工程；本工程不保存聊天或采购草案。
- 每轮调用均使用**当时最新已发布**的企业本体与分类树版本，重新校验当前草案，返回本轮版本、相对上一轮的规则变化、缺失项、无效项和需要采购员重新确认的受影响值。若原品类在新版中停用、移动导致含义变化或不再可确定，返回品类待确认，由 Agent 重新请采购员选择；不暗中沿用旧解释。
- 流程依赖条件（例如预算金额）不足时，返回“流程待确定”及缺少的决定因素；补齐后返回命中的企业审批流程版本、步骤、职位与依据。逐轮结果还返回“需求数据齐备/未齐备”和具体校验问题；按[第 10 项](./10-define-scoring.md)检查每采购项评分满分、必须项门槛及多采购项权重等本次数据约束。**数据齐备不等于获准发布**：发布权限、审批执行、正式发布和采购记录均由外部系统负责。
- 面向外部 Agent 的最小判定结果含：企业与分类/本体版本、品类候选或已确认路径、两组字段规则、当前值及来源、缺失/无效/需重确认项、流程状态与命中依据、数据齐备状态和可追溯理由。API 与 MCP 返回同一业务语义，MCP 不自行推导或改变发布结论。
