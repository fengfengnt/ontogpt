## Question

外部系统将已发布采购需求送达供应商 Agent 后，Agent 把该需求与乙方本次材料传给本工程。本工程怎样分别返回品类覆盖、逐条件“满足/不满足/缺资料/需人工核验”、可响应采购项及单供应商全覆盖结果？哪些可由已发布乙方本体直接判定，哪些只给出建议供甲方外部系统核验；结果应携带什么来源、版本和理由，避免 Agent 将“满足”误说成已正式入围？

## Answer

- 外部采购系统按权限将已发布需求送达乙方 Agent。乙方 Agent 可把该需求和本次材料传入本工程，独立查询本企业已发布本体并自检可响应采购项；自检不改变甲方既有匹配结果，不写入正式入围。甲乙 Agent 的首版交互限于准入条件澄清、补充证据或承诺，之后可再次调用本工程重判；价格及合同条款留给后续采购流程。对话和材料交换由外部系统承载。
- 本工程分别返回**品类覆盖**与**具体条件判定**。品类按[第 11 项](./11-define-category-semantic-matching.md)比较双方三级路径与描述，只有达到冻结的高相似度阈值、且 LLM 判为“等价”时才为“匹配”；“包含”、描述不足或无法判断仍是“待判定”，不算覆盖。具体品牌、价格、维保、案例等逐项关联乙方已发布本体事实或本次披露证据，不能仅因品类匹配而视为满足。
- 已确认的乙方本体事实、明确数值规则和可核验承诺可机器判“满足/不满足”；未提供材料显示“待乙方补资料”，截止仍缺则不满足；案例质量等主观项、未核验材料或冲突证据显示“待甲方核验”。乙方自述不能自动变成已确认事实。每项结果都给出条件类型、是否必须、规则/门槛、所用事实或证据及来源、判定理由和版本。机器可计分的必须项须达到甲方已确认的最低通过分，0 分不能入围；主观评分仍由甲方审核人完成。
- 对允许多供应商的采购，按每个采购项分别汇总。要求单一供应商时，乙方须对**全部**采购项有品类覆盖且通过所有必须项。总体只返回四态建议：`符合自动入围条件`、`待甲方核验`、`待乙方补资料`、`不满足`。明确不匹配的必需品类或不满足的必须项使结果为“不满足”；描述或证据缺失时为“待乙方补资料”；资料齐全但品类语义仍待判定、或主观/冲突条件待核验时为“待甲方核验”。全部必需品类匹配且所有必须项机器通过后，才可能为“符合自动入围条件”。加分项待核验不阻止准入，但其分数不能提前视为已得。
- 甲方企业本体保存经确认并发布的**自动入围政策**，外部采购系统对本次需求显式启用，传入可核验的授权记录、采购规则版本和入围截止时间。只有政策适用、授权有效、品类达到上述高阈值等价判定、全部必须项机器通过且无待补/待核验阻碍时，本工程才返回`符合自动入围条件`。外部系统可据此自动记录正式入围并发投标邀请；本工程不写入入围状态，也不向 Agent 声称“已正式入围”。未启用或无法核验授权时，即使条件满足，也返回需甲方处理的状态。
- 乙方 Agent 的自检结果须标明“自检建议”；甲方 Agent 以乙方对本次采购已授权披露的材料重判，才可供甲方外部系统采用。每次判定保留外部采购与响应标识、需求和证据版本、双方本体/分类版本、自动入围政策与授权记录引用、匹配模型和阈值、逐条件依据、汇总状态、调用主体与时间；这属于判定审计，不是采购业务台账。正式入围、邀请和投标状态只由外部系统提供。
- 用户选择允许**高阈值 LLM 品类匹配**直接参与自动入围条件，而第 11 项的试运行只统计同一 LLM 的自一致性，没有独立标注或误匹配率验收。因此自动邀请存在尚未量化的误匹配风险；所有自动判定应保留可追溯依据，后续取得独立样本时再校准阈值和验收规则。
- 后续[界定二级品类知识包与案例验收](./17-define-category-knowledge-pack-and-case-review.md)增加运行前人工预期与结果复核；误入围案例须修正并重测，相应品类才可启用自动入围。LLM 证据高相关仅筛证据候选，具体事实仍按知识包规则核验。
