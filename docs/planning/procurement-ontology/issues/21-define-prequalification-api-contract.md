## Question

外部采购系统不把采购需求及入围状态写入本工程时，资格预审判定请求如何传入本次经确认的采购项条件、知识包版本、乙方身份与声明/材料，返回逐项结果和四态汇总？知识包没有定义的新条件、乙方本次新声明如何在本次判定与后续本体确认之间流转？

## Answer

- 形成[资格预审判定 API/MCP 最小契约](../api/prequalification-v0.md)：一个乙方一次请求可带整单全部采购项；外部系统保存采购员原话、已确认结构化条件快照、采购/响应/正式入围状态，本工程按已发布甲乙本体、分类树、知识包和本次输入返回需求数据齐备状态、品类三态、逐条件结果、四态汇总及审计引用。甲方入围判定与乙方自检共用 API，但用途及可见范围不同；MCP 仅适配此 API。
- 采购员确认的本次条件优先于知识包默认建议，但不覆盖甲方已发布硬约束。原话与条件快照不一致，或如餐标 250 元/人违反企业上限 200 元/人时，返回差异/冲突及`需求数据未齐备`，不产生正式入围判断。每个本次新条件保留原文；LLM 可直接判断，即使条件带主观性，判满足仍可参与政策和本次采购预授权的自动入围。
- 资格预审按**乙方逐条件诚信申报**处理：乙方针对具体条件回答“有”即可作为本次判断依据，不强制上传证明文件；记录原话、身份、时间和项目范围。若乙方已发布本体记载相反事实，本次声明仍优先参与入围判断，同时向调用者显示冲突并生成乙方待确认候选；它不改写旧版本。完全没有相关已发布内容、项目材料或逐条件声明时才为待补。这个决定覆盖第 16、20 项中“主观项或冲突证据必须人工核验、缺原始证明不能通过”的首版假设。
- 本工程在**采购员确认条件快照后**自动为新条件创建甲方待确认候选；乙方新声明也自动生成乙方待确认候选。重复评估去重并只追加来源引用，外部 Agent 不需知道何时提交候选或调用单独创建接口。候选保留适用范围和来源，各自企业管理员审核发布之后才进入已发布本体。后续[乙方结构决策](./24-define-supplier-ontology-structure.md)明确：可复用承诺发布后默认通用，明确限定项目的材料仍限该项目。
- 品类高阈值等价只是初筛；逐条件满足、必须项门槛、单乙方全采购项覆盖以及已发布自动政策与本次显式授权仍要单独核对。甲方硬约束冲突挡住需求，乙方自述与旧乙方事实冲突则**提示但不阻断**本次入围。最终`符合自动入围条件`只是判定数据，外部系统才记录正式入围和发邀请。这个宽松诚信边界可能误入围，应通过运行前人工预期的案例复核发现和修正，未另设统一准确率门槛。
- 后续[知识包结构决策](./22-define-knowledge-pack-structure.md)进一步明确：客观数值条件与硬约束的业务判断也交 LLM，程序仅做基础结构、权限和分数合计校验；硬约束按企业本体中的适用范围生效。
