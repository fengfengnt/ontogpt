# 界定本体工程与外部 Agent 的业务边界

Type: grilling
Status: resolved
Blocked by: 12, 13

## Question

用户明确本工程分别向采购企业和供应商企业提供本体库，其他系统提供采购 Agent、供应商 Agent、聊天界面和采购业务记录。为让 Agent 通过 API/MCP 支撑从一句话采购到供应商邀请入围，本工程应返回哪些权威本体数据与判定结果，哪些对话编排、采购发布、供应商响应及入围记录由外部系统负责？现有第 12 项“查询加请求匹配”边界如何补齐？

## Answer

- 本工程分别维护采购企业和供应商企业的已发布本体及企业视图，对外通过版本化 API 与 MCP 提供**查询和判定**。外部系统提供聊天界面、采购 Agent、供应商 Agent、需求发布、供应商响应、正式入围记录和通知送达；本工程不承接这些采购业务写入动作。企业本体本身的候选确认与版本发布仍由本工程按[第 13 项](./13-define-enterprise-ontology-publication.md)管理。
- 采购 Agent 将“我要采购 100 个电脑”等表述及当前企业身份交给本工程，本工程识别本企业的采购负责类、一级品类、二级品类，并返回该品类采购时应收集的字段与规则，例如必填/可选、取值约束和可用默认值，以及适用职位与流程依据。**本次采购的具体品牌、预算、维保、交期等取值由采购人员给出**；Agent 负责补问，外部业务系统形成并发布本次采购项。按品类维护可复用字段规则与[第 01 项](./01-define-matching-business-contract.md)“每次采购项单独确定具体条件”并存。
- 采购需求由外部采购平台或消息系统按其权限送达供应商 Agent，本工程不主动推送。供应商 Agent 调用本工程时，将外部系统中的本次需求及乙方本次提交的材料作为判定输入；本工程结合乙方已发布本体、能力与甲方可披露的要求，返回逐采购项、逐条件的覆盖与满足情况、缺失项、待人工核验项、来源和版本依据。它可以保留判定审计，不把本次需求、响应或入围状态当作本工程的权威业务记录。
- “满足要求”是本工程返回给 Agent 和外部业务系统的可解释判定数据，不由本工程写成正式入围。客观且可核验的必须项与入围初评分可按甲方已发布政策机器判定；主观项和证据争议由甲方授权人员核验。若企业政策及本次采购均授权自动入围且全部必须项通过，外部系统可自动记录入围并发邀请；其余情况按[第 07 项](./07-define-explainable-matching.md)、[第 10 项](./10-define-scoring.md)和[第 16 项](./16-define-supplier-agent-shortlist-flow.md)处理。
- 本项修正[第 12 项](./12-define-agent-ontology-interface.md)将采购项、人工审核结果及入围状态视作本工程自有记录的表述；本工程的接口应增加按品类查询字段规则与流程、按外部传入需求评估乙方能力等只读/判定能力，不增加采购发布或入围写入工具。
