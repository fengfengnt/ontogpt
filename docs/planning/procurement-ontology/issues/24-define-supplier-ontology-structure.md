## Question

乙方本体中的可供应二级品类能力、可复用事实、来源、可检索标记和本次逐条件诚信声明应怎样分开建模与关联？乙方临时声明的新能力或项目承诺怎样用于本次自检和后续本体候选，并区分可复用承诺与明确限定项目的材料？

## Established boundary

- 乙方企业分类树与甲方独立，严格三级；能力记录引用乙方树的一个二级品类，企业可有多条能力及跨采购负责类经营。
- 可复用的乙方资格与经营事实经乙方确认发布在本体中；本次逐条件诚信声明和可选材料由外部系统传入。当前判定可用本次声明，即使与旧本体事实冲突，也须显示冲突并生成待确认候选。
- 原始附件、乙方响应、正式入围及合同记录归外部系统；本工程只留已发布本体、待确认候选和必要判定审计。
- 品类匹配只初筛，具体条件另判；乙方能力要标记为可供采购匹配后才进入查找。
- 本票不选图数据库、文档库或 RDF 表示，也不实现供应商后台页面。

## 用于检验选择的例子

乙方的已发布分类树有电脑与工服叶节点，但其已发布能力记录目前只有`办公物料 → 服装 → 工服`，却收到甲方的“100 台笔记本”采购需求。乙方 Agent 本次回答“我们也能供电脑，并承诺五年维保”，但还没有发布电脑能力，旧本体只记载三年维保。需要分别表达：

- 本次是否可把“供电脑”作为项目范围内临时能力参与品类匹配；
- “五年维保”是否可按诚信声明用于本次条件判断，并同时提示与旧事实冲突；
- 哪些内容进入乙方待确认候选、发布后对未来采购是否仍只限本项目；
- 常规采购检索在乙方发布电脑能力前，是否仍只能看到已发布的工服能力。

后面三点中的诚信声明优先、冲突提示和已发布能力才供全局检索，与既有判定及权限边界保持一致；本票主要定临时能力和事实范围的数据结构。

## 第一轮回答

- 乙方`SupplierCapability`与资格、品牌、团队、项目案例等事实分开建模，事实可关联多条能力。
- 每条事实标明企业、品牌、地域、二级品类、项目等适用范围及生效/到期时间。
- 乙方本次新声明的能力可在**本项目**自检与甲方重判中作为临时能力；发布前不进入常规跨甲方供应商检索，并自动进入乙方待确认候选。
- 用户选择：项目中的“五年维保”承诺一旦由乙方管理员确认发布，**默认成为通用事实**。明确写明“仅限项目 P”的原厂授权或材料仍限 P。这个决定覆盖第 21 项“项目专属声明不自动泛化”的旧边界。

## 第二轮回答与决议

- 可复用的能力与服务承诺在人工确认、管理员发布后，默认作为通用事实；源于某项目仍记录项目来源，但来源项目不自动成为适用范围限制。明确写出项目限制的原话或文件则保留该限制；品牌、地域、品类和有效期限制也不因发布消失。
- 乙方本次声明的新品类即使不在本企业已发布树中，也可用原话构造**仅本项目**的临时完整三级路径，供 LLM 品类匹配；相应新树节点和新能力进入各自的待确认候选，发布前不在全局查找中出现。
- 发布新能力时，乙方管理员须明确确认`可供采购匹配`开关。发布与进入常规检索分开；本次临时声明不自动打开该开关。
- 最小结构、来源和发布语义形成[乙方本体结构设计稿](../ontology/supplier-model-v0.md)。本票只确定产品结构，不实现存储或图形界面。
