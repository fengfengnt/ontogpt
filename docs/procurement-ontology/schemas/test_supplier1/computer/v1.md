# test_supplier1 / computer / v1：乙方提取规范

状态：待评审的第一版设计。目标文件为 `src/ontogpt/templates/company/test_supplier1/computer/v1/test_supplier1_computer.yaml` 和同名 `.py`；根类为 `SupplierComputerExtraction`。

## 1. 资料和目标

资料为用户提供的 `supplier-laptop-bid-case.md`，站在模拟中标方“上海联畅科技有限公司（联想代理商）”视角撰写；当前文件 SHA-256 为 `F435BBD2439F736AA0EBEB0C05E642EEDF3092145A5D21006AE997EC9484F346`。实施时在服务测试 fixtures 中固定此模拟副本，不能把它宣称为已核实真实企业材料。

目标是提取本企业供应事实陈述、资格、授权、供给/交付/售后能力，以及带项目和阶段范围的内部成本、报价与策略。乙方获准读取本体的用户可以直接查询这些已发布内容；甲方和平台管理员不能读取。

与甲方共用 `computer` 品类键及显示名称，但提取根类、字段、关系、YAML、Python 和文档独立维护。

## 4. 业务关系

| 关系类型 | 主体 → 客体 | 用途 |
| --- | --- | --- |
| `authorized_for` | 授权陈述 → 产品供给或项目证据 | 限定授权适用对象。 |
| `provides_service` | 产品供给 → 交付/售后能力 | 关联所含服务，不凭型号推定服务承诺。 |
| `supported_by` | 能力陈述 → 项目证据 | 保留材料给出的能力证据。 |
| `cost_of` | 内部成本 → 产品或项目证据 | 说明金额的成本对象和核算范围。 |
| `strategy_for` | 报价策略 → 项目或产品供给 | 限定报价策略适用对象。 |

服务附加对本企业二级品类的归属。引用客户或竞争者名字仅是本企业知识中的提及，不能变成另一企业数据域的连接。

## 5. 必须保留的冲突和阶段差异

原文商业分析段写数据迁移“成本约 600 元”，成本表又写迁移人工成本 `1,200 元`。提取应保留两条来源陈述和上下文，在相同项目及可比口径下提出冲突；模型不能擅自选一个金额覆盖另一个。

初始报价与最终报价要按轮次区分；能力“20 天”、对外承诺“25 天”、客户要求“30 天”要按性质区分。它们可能同时成立，不能只保留最小值或最大值。

材料中的“中标”“满足资格”“必然胜出”等均是模拟资料作者的陈述。允许保存和引用其来源性质，不由本系统重新作资格判断、中标确认或真实商业背书。

## 6. schema 验收点

| 编号 | 输入 | 应有结果 |
| --- | --- | --- |
| S-01 | 年度代理和本项目授权 | 类型、品牌和项目范围分开，证据可定位。 |
| S-02 | 设备单价、项目总成本、完整单位成本 | 不混淆金额对象、币种、税口径和估算状态。 |
| S-03 | 600 元与 1,200 元迁移成本 | 两条原文均保留，冲突交给审核，不静默覆盖。 |
| S-04 | 928,000 与 885,000 元报价 | 带不同轮次，不作为同阶段无条件冲突。 |
| S-05 | 成本/报价策略发布后查询 | 本乙方可读，甲方和平台不可读。 |
| S-06 | 模型发明资质、有效期或另一企业引用 | 待补证或拒绝发布，不生成跨企业访问能力。 |

上述结果须通过实际模型调用、企业权限测试和人工核对验证；本轮只完成规范设计。
