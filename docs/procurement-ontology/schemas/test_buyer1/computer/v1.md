# test_buyer1 / computer / v1：甲方提取规范

状态：待评审的第一版设计。目标文件为 `src/ontogpt/templates/company/test_buyer1/computer/v1/test_buyer1_computer.yaml` 和同名 `.py`；根类为 `BuyerComputerExtraction`。

## 1. 资料和目标

资料为仓库 [甲方模拟案例](../../../../../tests/fixtures/procurement/laptop-purchase-case.md)，SHA-256 为 `AF2A287082514526FF4413900EFAE65AF99B4C10827DB619CAECB290E8F5ED45`。既有 [知识包候选 V0](../../../laptop-knowledge-pack-candidate-v0.md) 是解释和评审参考，不能替代原文提取。

目标是提取本企业电脑二级品类知识包：应采集什么信息、怎样表述条件模板、如何区分术语和采购阶段。项目数量、预算和具体门槛只作为带范围的案例值。本系统不执行资格判定、评分或采购流程。

归属路径为 `IT与通讯 → 办公设备 → 电脑(台式机/笔记本)`，本案例主要适用 `办公笔记本`。来源没有台式机专有知识时，不用笔记本配置填补台式机条目。

## 2. 根类与字段组

| 根字段 | 候选类型 | 主要业务字段 |
| --- | --- | --- |
| `collection_fields[]` | `CollectionField` | `field_name`、建议提问 `question`、值类型、单位、案例值 `example_value`。 |
| `condition_templates[]` | `ConditionTemplate` | 条件类别、`condition_text`、需向乙方取得的信息、案例门槛、适用阶段。 |
| `term_definitions[]` | `TermDefinition` | `term`、定义或解释、需区分的概念。 |
| `process_notes[]` | `ProcessNote` | 阶段、知识性说明、与其他阶段的关系；不保存本次流程的操作状态。 |
| `relations[]` | 业务关系候选 | 主体局部引用、关系类型、客体局部引用、证据摘录。 |

每个业务条目另有 `label`、`statement`、`evidence_quote`、`device_type`、`project_ref`、`stage` 和可空的有效期原文。没有来源时不能填造时间范围。正式 ID 和分类 ID由服务分配或解析。

`ConditionTemplate` 的类别区分资格、技术、商务、评分说明。比较条件保留原文和结构化数值作为案例信息；不生成自动执行的采购判定代码，也不把案例中的“必须”自动变成整个品类的永久规则。

## 4. 业务关系

| 关系类型 | 主体 → 客体 | 用途 |
| --- | --- | --- |
| `requires_information` | 条件模板 → 采集字段 | 说明评估该模板需要哪些乙方信息。 |
| `explains` | 术语解释 → 条件或知识条目 | 为理解条件提供语义说明。 |
| `precedes` | 阶段说明 → 阶段说明 | 表达材料说明的阶段顺序，不驱动工作流。 |

`belongs_to_category` 由服务附加，指向本企业既有二级品类。设备类型、项目和阶段优先保存在范围字段，不为了画图把每个字符串都扩成新节点。未有原文支持的推导关系保持建议状态。

## 5. 输出与发布示例

对保修原文提取：服务方为原厂、年限为 3 年、服务方式为上门、响应为下一工作日到场，范围固定为本模拟项目和办公笔记本。审核可以形成可复用的“保修信息采集字段”或“保修条件模板”，但需保留其案例来源以及管理员确认。

既有候选 V0 中的终端兼容性建议 `F12` 没有案例中的具体兼容清单，应保持建议或要求管理员补充来源。不能因为它出现在候选说明文档中就当作企业已经提供的原文事实。

## 6. schema 验收点

| 编号 | 输入 | 应有结果 |
| --- | --- | --- |
| B-01 | 数量、预算、单价目标 | 分别提取，案例值带项目范围，企业默认值不自动填充。 |
| B-02 | 原厂 3 年上门 NBD | 四个服务维度保留，来源摘录可定位。 |
| B-03 | 资格预审通过、后续方案废标 | 两个阶段分开，不自动输出入围或淘汰结论。 |
| B-04 | 常识建议或重复且无明确位置的摘录 | 留待补证，不可直接发布。 |
| B-05 | 新的当前 schema 不支持的关系 | 保存缺口，起草待审新版，当前 `v1` 和启用指针不变。 |

上述结果须通过实际模型调用和人工核对验证；本轮只完成规范设计。
