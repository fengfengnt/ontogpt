| 1 | 根仓库仅运行离线 unit 基线，服务运行全套测试，避免无关付费调用。 | 根集成行为改变时须针对性追加验证。 |
| 2 | uv 安装期间使用现有根解释器观看 Task 1 RED；安装完成后使用标准 uv 命令 GREEN。 | RED/GREEN 使用不同解释器环境，但测试相同，最终以服务环境为准。 |

| 7 | 使用经过 SHA-512 核验的官方完整 Fuseki 6.2.0，固定 Java 21 基础镜像并启用认证。 | 维护自建镜像；不能用缺少动态数据集管理的简化 server kit 替代。 |
| 8 | 不可变版本图同事务保存 rdf:JSON 无损业务载荷及语义 RDF，关系用 rdf:Statement 保存证据。 | 必须经统一 codec 操作，禁止两份表示各自编辑。 |

| 10 | 审核/发布审计嵌入快照事务，提交后批次状态断写可由不可变快照修复。 | 恢复只信任同数据域已发布快照。 |
| 11 | 缺口发现必须接收已保存原文，草案生成必须接收已验证 binding。 | 调用方传入可信服务对象，不接受模型控制路径。 |
| 12 | 使用锁定的 MCP 2.3 MCPServer、structured_output 和认证无状态 HTTP。 | 调用方遵守该 SDK 版本，不自建 JSON-RPC 仿制协议。 |
| 13 | 企业初始化重试继续使用第一次冻结的平台版本对。 | 重试不会改用此后更新的通用模板，保留原账号。 |
| 14 | 画布和 Agent 菜单分别随 Task 12/13 实际组件落地。 | Task 11 阶段入口暂不完整，最终验收前补齐。 |
| 15 | 共享进程内维护闸门覆盖完整业务写和两种存储，CLI 文件锁要求先停服务。 | 只支持单进程，一个数据集前缀只能绑定一个运行目录。 |
| 16 | BackupManager 绑定恢复目标；导入前验证，只恢复到空 SQLite/运行目录及空前缀，失败留下禁止启动标记。 | 验证后再切换；草案工作树文件需额外用 Git 保存。 |
| 17 | FAILED 重试保留稳定 run ID，但分配新不可变候选批次。 | 客户端使用本次返回的 batch_id，旧失败批次留存审计。 |
