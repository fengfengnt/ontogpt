# 前端设计

状态：独立 React/Vite 应用已实现工作区、来源/审核/发布、Schema 草案、树菜单、企业画布及甲方问答，组件测试与构建通过；真实模型和浏览器验收按实施计划继续。技术选择依据见 [系统架构](system-architecture.md)。

## 1. 前端技术栈

| 选择 | 用途 |
| --- | --- |
| React + TypeScript + Vite | 独立管理应用、类型化页面和开发构建。 |
| Cytoscape.js | 企业业务本体的局部图展示、节点/边选择和关系操作。 |
| 浏览器 `fetch` | 同源调用 FastAPI；会话、错误和版本信息集中处理。 |
| 普通 CSS + 语义 CSS tokens | 页面与画布统一视觉规则，集中替换颜色、字体及间距。 |
| Vitest | 对菜单、操作生成、版本冲突和引用展示作有意义的测试。 |

MVP 不引入大型组件库或全局状态框架。页面保留当前读取结果、表单输入和待提交操作；权威知识、批次状态及权限由服务端返回。

## 2. 工作区与导航

| 工作区 | 一级菜单 | 数据范围 |
| --- | --- | --- |
| 企业 | 资料与提取、候选审核、本体画布、三级分类树、Schema 改进、发布记录 | 当前登录企业。 |
| 甲方测试账号 | 另有本体问答测试 | 固定 `test_buyer1 / computer`；乙方和平台不显示或调用此入口。 |
| 平台 | 通用本体、通用三级树 | 平台数据集。 |

企业页面顶部显示企业名称和当前二级品类，不能选择另一企业。平台的企业开通操作只展示企业 ID、开通状态等系统元数据，不提供“进入企业知识”按钮。隐藏菜单仅是界面行为，API 权限必须独立验证。

## 3. 企业本体画布

```text
┌ 当前企业 / 当前二级品类 ─────── 树版本、本体版本 ───────┐
│ 只读分类导航 │ 当前品类局部图与待审变更 │ 属性与来源面板 │
│ 批次列表     │ 条目、关系、归属        │ 类型、范围、原文 │
│             │                        │ 模拟、审核状态   │
├─────────────┴────────────────────────┴──────────────┤
│ 保存到待审批次 / 查看差异 / 校验结果 / 发布（有权限）   │
└─────────────────────────────────────────────────────┘
```

画布可以新增、修改和移除知识条目及允许的关系。连线后必须选择关系类型并检查来源；条目对分类节点的归属可修改为服务端允许的既有分类节点。画布中的分类节点只用于导航或展示归属，不提供增删改操作。

右侧表单显示标签、说明、业务属性、设备类型、项目/阶段/有效期、来源片段、模拟标记和审核状态。关系也有自己的来源及范围，不能因为两个端点存在就自动认定关系成立。

“保存”表示提交至待审批次。“发布”表示通过服务器校验后创建正式新版本。已发布内容与待审变更使用文字标识和视觉状态区分，不能只靠颜色。移除旧关系在差异视图中显示为待移除，发布后才影响普通读取。

收到 `VERSION_CHANGED` 或 `STALE_BASE_VERSION` 后，保留本地尚未提交的表单以便核对，停止继续提交旧基础版本，并明确提示刷新和重新检查差异。不能直接把整张浏览器图覆盖服务器。

## 4. 三级分类树菜单

独立页面用展开/折叠树展示 `采购负责类 → 一级品类 → 二级品类`。企业管理员只操作本企业树；平台管理员在通用树菜单操作平台树。

节点操作为新增下级、修改名称、调整合法父级、删除。二级品类不能增加第四层子节点。删除时显示引用检查结果；被已发布本体引用时，提示先处理本体引用并发布，而不是级联删除知识。

树页面显示当前版本、待审差异及发布状态。改名不改变稳定节点 ID、`category_key` 或已保存的 schema 路径。画布侧的分类导航随服务器返回的新树版本刷新。

## 5. 平台通用本体与初始化提示

平台通用本体使用独立的条目列表和属性/关系编辑表单，沿用来源、范围、审核、差异和发布规则。MVP 不必为平台另做一套企业画布。

通用本体和通用树的发布页明确显示：“新版用于之后新建的企业；已建企业不会自动同步。”企业页面可显示其初始化采用的平台来源版本，不能把该标识做成可绕过授权的跨数据集浏览入口。

## 6. Schema 改进与问答

Schema 改进页面接收自然语言描述及来源，展示系统发现的缺口、新版本 YAML 差异、生成结果和审核状态。页面不能把草案切换成正式启用版；启用由审核人完成 Git 审阅、测试、部署后执行管理命令。

甲方问答页包含问题输入、答案、实际工具引用的条目 ID、来源片段及版本。无依据时显示“未找到可引用的已发布依据”；不能在界面上把模型建议画成已确认知识。用户可以点开本企业获准读取的条目详情。

## 7. 界面风格及替换

初始风格参考已选的 [Claude `DESIGN.md`](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/claude/DESIGN.md)：暖色纸面、克制的珊瑚色强调和清晰排版。项目自己的 `DESIGN.md` 说明实际设计约定；不使用第三方标志或专有字体作为产品资产。

建议的语义 token 名称包括 `--surface-page`、`--surface-panel`、`--text-primary`、`--text-muted`、`--accent`、`--status-pending`、`--status-error`、`--graph-node-fill`、`--graph-edge-stroke`、`--font-body` 和 `--radius-panel`。这些名称表达用途，不能把某品牌色名写进业务组件 API。

Cytoscape 样式从同一 tokens 读取，并在样式变化后显式刷新。图节点类型、来源状态、企业范围和发布状态属于业务含义，不因视觉风格变更而改变。

以后采用 [MiniMax `DESIGN.md`](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/minimax/DESIGN.md) 一类新风格时，更新项目 `DESIGN.md`、tokens 和必要的组件布局，再检查管理页、树菜单、画布和问答页。只改 Markdown 不会自动改变已构建应用；颜色字体替换较集中，导航和信息密度变化仍需调整组件。MVP 不交付运行时换肤开关。

## 8. 可用性与浏览器评审

树菜单、属性表单和图操作均提供明确标签、键盘可达按钮、可见焦点和错误提示。图的重要编辑操作可通过属性面板完成，避免必须精确拖拽才能操作。发布、删除和待审状态除颜色外有文字说明。

浏览器评审分别以甲方、乙方、平台账号检查导航、权限错误、树和画布边界、来源可读性、窄窗口布局及字体对比度。构建通过只证明可构建，不能代替这些界面操作与视觉检查。
