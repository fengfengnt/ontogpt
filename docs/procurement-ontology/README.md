## 文档之间的关系

已确认的 MVP 设计是范围与原则的依据。本目录补充可供实施和评审的细节；实施计划引用这些文档并安排任务。如果实施时发现细节与已确认设计冲突，先记录冲突和处理决定，再调整相应文档，不能默默扩大范围。

`laptop-knowledge-pack-candidate-v0.md` 是既有甲方建模候选样本，包含原文依据、用户修订和待补证建议。它不是已发布企业本体，不代替模型提取或人工审核。2026-10-16 的设计和计划是历史资料。

## 已确认范围与执行授权

- 已确认 `test_buyer1`、`test_supplier1` 各自独立的 `电脑(台式机/笔记本)` schema、三级树和本体。
- 已确认 SQLite 保存启用 schema 指针，Fuseki/TDB2 保存业务知识及其发布版本。
- 已确认画布只编辑企业本体数据；三级树在独立树形菜单增删改；平台管理员只管理通用本体和通用树。
- 已确认新企业取得通用本体和通用树的独立实例，通用版本以后更新不自动同步到已建企业。
- 用户已选择后续由当前任务逐项实施，不再重新选择执行方式。
- 文档暂停点已经履行，用户已明确授权继续；文档已合入当前工程，实施在隔离分支进行，完成后集成回当前工程。

## 当前验证状态

真实模型提取、三类账号浏览器实操、WSL Docker 部署、TDB2 发布原子性、SQLite 激活事务及双库恢复已完成技术验证。详见[验收记录](acceptance-2026-10-20.md)与[服务启动说明](../../services/procurement_ontology/README.md)。模型候选和 v2 草案仍需要人类业务审核，不等于正式上线验收。
